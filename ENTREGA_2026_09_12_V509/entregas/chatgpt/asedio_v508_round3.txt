POLYDIM V508 - ROUND 3 BULLDOG EVIDENCE
2026-09-12

[FACT 1] C++ original does not compile on GCC/Linux as delivered.
Command: g++ -x c++ -std=c++17 -shared -fPIC -O2 kernel_cpp_v508.cpp.txt
Observed: __declspec(dllexport) causes parse errors.
Additional portability defects: __cpuid spelling/API is MSVC-specific; sqrtf/acosf/sinf lack <cmath> declaration in the submitted translation unit.

[FACT 2] PmtpMonolito imports but construction without native libs crashes.
Observed with nonexistent base_dir: AttributeError: 'NoneType' object has no attribute 'pmtp_phase99_swarm_consensus'
Cause: _load_libs() stores None, then _bind_rust_ffi dereferences None.

[FACT 3] CPU-only PmtpTensorHandle default path is broken.
Environment: torch 2.10.0+cpu, CUDA unavailable.
Observed: tensor.pin_memory() -> RuntimeError: Cannot access accelerator device when none is available.
Cause: require_pin=True unconditionally invokes pin_memory.

[FACT 4] Rust/Python SeqLock ABI is inconsistent.
Rust begin_write: (*mut u64) -> u64
Rust end_write: (*mut u64, u64) -> ()
Python binds begin as (void*) -> int64 and end as (void*) -> int64.
Python therefore cannot call end_write according to the declared ABI and never binds the token argument correctly.

[FACT 5] Python slab writer does not use Rust atomic SeqLock.
write_slab_atomic -> _atomic_seq_increment -> ctypes uint64 += 1.
The Rust atomic functions are defined but not called by the slab path.
Therefore SeqCst Rust ordering does not protect actual writes.

[FACT 6] Rust begin_write is not a writer-acquisition operation.
fetch_add(1) is not a CAS loop enforcing odd ownership. Two writers can race and produce an even seq while one writer is still writing. A reader can then accept an inconsistent slab. Required primitive: compare_exchange loop from even->odd, with one writer owner.

[FACT 7] Rust phase99 ignores dim for memory safety.
It creates slices using fixed D_DIM=10000 regardless of dim. dim is caller-supplied but not validated. If caller supplies dim<10000 while buffer is shorter, Rust reads/writes beyond the logical object; if caller supplies dim>10000, excess data is silently ignored.

[FACT 8] Rust phase99 has no pointer validation.
For num_neighbors>0 it calls from_raw_parts_mut/local and from_raw_parts/neighbors/weights without null/alignment/length checks. The early return for num_neighbors==0 is not a general NULL safety guard.

[FACT 9] Rust phase99 returns success for num_neighbors==0, including NULL local.
That is semantically dangerous for an FFI API advertised as panic/NULL guard. Either reject NULL consistently or define a no-op contract explicitly and test it as success.

[FACT 10] dt is dead API input in phase99.
The function accepts dt but update is local += gamma * projected_drift; dt never participates. Therefore changing dt has no effect. This is not merely optimization; it changes the mathematical meaning of the advertised Euler step.

[FACT 11] CBF semantics are conflated.
cbf_gamma is used directly as the update gain. No barrier condition is actually implemented. Name/documentation claims a Control Barrier Function margin, implementation is a weighted tangent drift step.

[FACT 12] phase99 heap allocation is O(D) per call.
let mut drift = vec![0.0f32; D_DIM];
At 50k calls this allocates/frees roughly 2 GB of transient payload traffic at D=10000, even if allocator caching hides RSS growth. This can dominate latency and destroy deterministic realtime behavior.

[FACT 13] Consensus weights are not validated.
num_neighbors may disagree with weights length; weights pointer may be NULL with num_neighbors>0. No finiteness checks for local/neighbors/weights/dt/cbf_gamma. NaN/Inf can poison drift and output.

[FACT 14] C++ exact antipodal SLERP is reproducibly NaN.
Compiled the submitted SLERP body on GCC after isolating it from the unrelated Windows-only wrapper.
Input: v0=e1, v1=-e1, dim=10000, t=0.5.
Observed: finite=False, nan=10000, norm=nan.
Cause: Gram-Schmidt orthogonal component has norm zero; 0 * inf generates NaN. The claimed antipodal fix therefore fails on the canonical worst case.

[FACT 15] C++ SLERP standard path does not clamp dot to [-1,1].
Only threshold comparisons are present. Rounding can make dot slightly outside the acos domain. Required: dot = clamp(dot,-1,+1) before acos.

[FACT 16] C++ SLERP has a fixed stack array float ortho[10000].
If dim>10000, the function writes past the array. Comment says “assumimos dim=10000”, but API accepts arbitrary size_t dim. This is a direct memory-safety boundary failure.

[FACT 17] C++ SLERP does not handle zero-norm inputs.
Near-parallel branch normalizes without checking norm_sq; antipodal branch divides by v0 norm and ortho norm without zero checks. Invalid inputs can yield Inf/NaN.

[FACT 18] validate_alignment() has the wrong C++ ABI.
C++ function: (const void*, int) -> int.
Python calls: (void*, uint64 size_bytes, int min_dim).
Extra argument and semantic mismatch. Because _bind_cpp_ffi is pass, ctypes also provides no explicit argtypes/restype contract. This is ABI-unsafe.

[FACT 19] validate_topology() is unfinished.
It constructs union-find arrays then returns None. A1/A2 in the attack battery cannot validly certify beta_1.

[FACT 20] A8 test is ABI-invalid.
Python calls pmtp_phase99_swarm_consensus with 6 arguments; current Rust signature requires 7. The test is therefore not testing the actual function contract.

[FACT 21] Fuzz test swallows all failures.
except Exception: pass
Therefore the loop can fail 50,000 times and the final output can still claim stability. It is a false-negative test harness.

[FACT 22] Fuzz test cannot establish “0 leaks” from one RSS delta.
0.52 MB RSS delta is not a leak proof. RSS includes allocator arenas, lazy mappings and runtime state. Need allocation instrumentation, repeated create/destroy cycles, stable workload, and preferably ASan/LSan/heap profiling where applicable.

[FACT 23] FJLT test is not an FJLT test.
It generates Rademacher signs and checks norm preservation. That validates an elementwise signed isometry, not the Fast Johnson-Lindenstrauss Transform pipeline (which requires structured transform + subsampling/projection and embedding distortion measurements).

[FACT 24] Qwen “zero-copy” test is a copy/mock test.
Fallback PMTPContext stores self.memory = np.copy(tensor) and read() returns np.copy(self.memory). It never validates actual IPC mapping between independent processes/nodes. Therefore drift==0 only proves NumPy copied identical bytes.

[FACT 25] PMTP Qwen test does not feed latent state into Model B.
model_b is loaded but the reconstructed latent_tensor_b is not used as input to any Model B continuation. The test verifies byte equality of arrays, not cross-node model interoperability.

[FACT 26] Triton normalizer output contract lacks aliasing check.
out is assumed distinct. If x and out alias, partial norm can still work but writes may alter later reads depending on launch scheduling; contract should explicitly reject aliasing or document support and test it.

[FACT 27] Triton normalizer does not reject non-contiguous out.
Only x has contiguity assertion. out is written as a flat pointer with implicit contiguous addressing, so a non-contiguous tensor view can be corrupted logically.

[FACT 28] Triton final norm maps non-finite total to zero indirectly.
tl.where(total > 1e-24, rsqrt(total), 0.0) does not express an explicit finite/NaN policy. NaN comparisons are false, so NaN input can silently produce inv=0 and an all-zero output instead of surfacing an error.

[FACT 29] Triton async buffer recycling is stronger than the tested contract but still has lifecycle hazards.
The slot is released after cloning/synchronizing through done_event, which is reasonable, but there is no cancellation handling for pending poll callbacks/futures and close() only shuts the executor. There is no explicit stream/event/device teardown contract.

[FACT 30] Slab shared-memory ownership is not exclusive across processes.
os.open(... O_CREAT|O_RDWR) + ftruncate permits multiple writers to attach to the same named slab. The per-process threading.Lock does not serialize them. Without an actual inter-process writer lock, the one-writer premise is false.

[FACT 31] Slab persistence leaks namespace objects.
close() closes mmap/fd but does not unlink /dev/shm/POLYDIM_SLAB_<id>. Repeated unique slab_ids leave persistent shared-memory files until external cleanup.

[FACT 32] close() is best-effort rather than lifetime-safe.
It catches BufferError from mmap.close() and continues. An exported memoryview/ctypes pointer can keep the mapping alive, yet the object proceeds as if closed. This makes ownership state ambiguous.

[FACT 33] Library names are identical for Rust and C++ on Linux.
rust_name and cpp_name both resolve to libpmtp_kernel_v506.so. The cache key/path is therefore the same, so _rust_lib and _cpp_lib resolve to the same library rather than two independently built components. This is catastrophic if separate symbols/builds are intended.

[FACT 34] Version skew is present inside V508.
Archive is V508 but monolith docstrings and names still say V505/V504/V506; README says Version 507.0. Native names are v506. This makes reproducibility and artifact provenance ambiguous.

[FACT 35] The README's Mooncake attribution does not support the specific “<64KB TLB trap” claim.
Current Mooncake FAST'25 materials describe KVCache-centric disaggregation and large-scale RDMA/CPU/DRAM/SSD utilization, but the cited material does not substantiate the supplied universal 64KB/TLB-shootdown law. The slab design may still be a useful engineering choice, but the causal theorem is unsupported by the cited source.
